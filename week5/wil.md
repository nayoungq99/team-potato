# SOLID 원칙과 스프링 빈
## 1. 객체 지향 
### 객체 지향 프로그래밍(OOP)
- 객체들의 상호작용으로 파악하고자하는 컴퓨터 프로그래밍의 패러다임
- 프로그램 묶음 단위로 잘라서 조립하듯 프로그램 완성
- 유연하고 변경 용이 --> 대규모 소프트웨어 개발에 사용

### 객체 지향 특징
- ``추상화``
- ``캡슐화``
- ``상속``
- ``다형성`` -> 어떤 역할에 대해 **다양한 구현 방식**이 존재할 수 있음. -> 프로그램 유연, 변경 용이

**☑️ 다형성 특징을 사용해 역할을 만들어 놓고 그 역할 수행하는 구현체 바꿔가며 적용해보자**  
  

역할 -> 인터페이스(클래스가 구현해야 하는 메소드 집합, 클래스의 설계도)  
구현 -> 인터페이스 구현한 클래스

## 2. SOLID 원칙
좋은 객체 지향 설계 위한 5가지 원칙  
1) ``SRP : 단일 책임 원칙(single responsibility principle)``  
하나의 클래스는 한 개의 책임, 클래스 변경하는 이유는 하나여야 수정이 쉬움.  
--> 프로그램 **유지보수성** 높임   

2) ``OCP : 개방-폐쇄 원칙 (Open/closed principle)``  
클래스는 확장에 열려있고 (새로운 변경사항 있을 때 유연)  
수정에 닫혀있어야 함. (새로운 변경사항 있을 때 기존 코드 변경 제한).
3) ``LSP : 리스코프 치환 원칙 (Liskov substitution principle)``  
자식 클래스가 부모 클래스 대체할 수 있어야 하지만 부모 클래스의 기능 변경은 X.  
--> 문법 상속, 타입 호환성 넘어 **행동적인 호환성**까지 보장되어야 함.
4) ``ISP : 인터페이스 분리 원칙 (Interface segregation principle)``
인터페이스를 사용에 맞게 잘 분리하고 클라이언트의 목적과 용도에 적합하도록 함.  
하나의 큰 인터페이스보다는 **여러 개의 작은 인터페이스**로 분리.  
--> 인터페이스 명확, 대체 가능성 높음
5) ``DIP : 의존관계 역전 원칙 (Dependency inversion principle)``  
추상화에 의존 O, 구체화에 의존 X  -> 구현 클래스에 의존 말고 **인터페이스에 의존.**  
의존 관계 설정 시 변화 어려운 곳에 의존.

---> 다형성만으로 SOLID 원칙 지키기 어려움. 따라서 스프링은 **의존성 주입** 지원.

### IoC
제어의 역전  
객체 생성 및 관리에 대한 제어권을 프레임워크가 대신 가져감!  
스프링에서는 객체 생성, 관리하는 역할을 스프링 컨테이너. 이를 IoC 컨테이너라고도 함.

## 3. Spring Bean
-  **수동 등록**: 설정 파일 작성  
 -> @Configuration으로 설정 클래스 생성  
 -> 반환하는 메서드에 @Bean 붙이기  

- **자동 등록**: 컴포넌트 스캔
 -> 컴포넌트 스캔(@ComponentScan): 어떤 클래스가 스프링 빈인지 찾아서 등록.
 -> 컴포넌트(@Component): 어떤 클래스가 스프링 빈인지 표시!  
 -> 빈으로 등록하고 싶은 클래스에 @Component 붙이기

### DI
- 의존성 주입, IoC를 구현하는 방법  
- 내가 의존하는 객체를 직접 생성 않고 밖에서 주입 받음.
- 스프링 컨테이너에 필요한 객체(Bean) 미리 생성, 다른 객체에서 이 객체 필요할 때 주입.
- 느슨한 결합 -> 한 클래스의 변경이 다른 클래스에 미치는 영향 최소화.
- 유연성, 유지보수성 높임

### 의존관계 자동 주입
@Autowired: 필요한 타입의 객체를 자동으로 찾음

### 의존성 주입 방법
1) 생성자 주입
가장 권장, 객체 생성시 필요한 의존성 함께 주입.  
생성자 호출 시점에 단 1번 호출, 불변성  
생성자 하나면 @Autowired 생략 가능  

2) 수정자 주입
변경 가능성 있는 의존 관계에 사용  
선택적인 의존성 주입 가능  

3) 필드 주입
권장 안함, 의존성 변경 가능성 있으며 테스트 힘듦...  
의존 관계 명확하지 않음

### 조회되는 빈 2개 이상일 때
- @Qualifier: 빈에 추가 이름표 붙임
- @Primary: 우선순위 정함.
